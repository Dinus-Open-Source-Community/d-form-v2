# Patching Ticket — BE-P1-002

## Ringkasan

| Field | Nilai |
| --- | --- |
| Ticket | `BE-P1-002` |
| Klasifikasi | Security — OAuth account linking |
| Prioritas | P1 |
| Baseline | `b73c643` pada branch `dev-zapp` |
| Commit code | `f9443de` |
| Status kerja | `In Review` (status `Done` tetap untuk human) |
| Scope | OAuth Google/GitHub linking, regression test, E2E, toast hard-load |

`OAuthController` menautkan akun lokal berdasarkan email provider tanpa
mensyaratkan provider menyatakan email tersebut verified, dan membuat email
sintetis `<nickname>@github.local` ketika GitHub tidak mengirim email. Perbaikan
ini menjadikan provider subject ID sebagai identitas utama dan hanya memakai
email untuk linking bila provider menyatakan email verified.

## Bukti sebelum patch

- **Confirmed** — `app/Http/Controllers/Auth/OAuthController.php:29-56`: Google
  mencari user berdasarkan `google_id`, lalu fallback ke email, lalu
  `Auth::login()` tanpa mensyaratkan `email_verified === true`.
- **Confirmed** — `app/Http/Controllers/Auth/OAuthController.php:100-139`:
  GitHub fallback ke email tanpa status verified dan membuat
  `<nickname>@github.local` dengan `email_verified_at = now()`.
- **Confirmed** — Socialite `v5.31.0`
  (`vendor/laravel/socialite/src/Two/GithubProvider.php`): default scope
  `user:email`, dan `getEmailByToken()` hanya mengembalikan email
  `primary && verified`. `buildProvider()->scopes($config['scopes'] ?? [])`
  menggabungkan scope default, sehingga `user:email` tetap diminta walau config
  tidak mendeklarasikan scope.
- **Confirmed** — Socialite `v5.31.0`
  (`vendor/laravel/socialite/src/Two/GoogleProvider.php`): raw userinfo
  dipertahankan, termasuk claim `email_verified`.
- **Reference** — Google OpenID Connect:
  `email_verified` true bila email sudah diverifikasi, dan `sub` adalah
  identifier utama yang tidak berubah.
  <https://developers.google.com/identity/openid-connect/openid-connect>
- **Reference** — OWASP Authentication Cheat Sheet, Secure Federated Account
  Linking: jangan auto-link hanya karena klaim email match; auto-link berbasis
  email yang verified adalah trade-off yang dipilih ticket ini.
  <https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html>
- **Reproduced** — test baru merah sebelum implementasi: **10 failed, 6 passed
  (55 assertions)**.

## Keputusan yang disetujui user

1. **Auto-link saat login** bila provider menyatakan email verified dan email
   sama persis dengan akun lokal (case-insensitive, normalized). Ini mengikuti
   acceptance ticket, bukan varian OWASP yang lebih ketat (wajib sesi
   terautentikasi sebelum linking).
2. **GitHub tanpa primary+verified email: tolak.** Redirect ke `/auth/login`
   dengan pesan netral; tidak membuat akun, tidak membuat email sintetis.
3. Report disimpan di `docs/big-changes/patching-ticket/BE-P1-002.md`.

## Perubahan

### `app/Services/Auth/OAuthAccountLinker.php`

Service baru, satu tanggung jawab: resolve identitas OAuth menjadi `User`.

- Provider subject ID (`google_id`/`github_id`) dicek lebih dulu.
- Email hanya dipakai bila `verifiedEmail` non-null:
  - Google: `email_verified === true`;
  - GitHub: email dari Socialite (primary+verified) non-null.
- Email dibandingkan case-insensitive dengan `LOWER(email) = ?` setelah
  `mb_strtolower(trim(...))`.
- Akun dengan provider ID berbeda untuk provider yang sama ditolak (tidak
  menimpa atau login ke akun yang sudah tertaut ke identitas lain).
- Email milik akun soft-deleted ditolak agar tidak membuat baris baru yang
  menabrak unique index.
- Akun baru hanya dibuat dari email verified, dengan role `member` dan
  `email_verified_at = now()`.
- `email_verified_at` hanya diisi bila email provider verified **dan** sama
  dengan email lokal.

### `app/Http/Controllers/Auth/OAuthController.php`

- Google: `email_verified` diparse ketat dengan
  `filter_var(..., FILTER_VALIDATE_BOOLEAN, FILTER_NULL_ON_FAILURE) === true`.
  Cast `(bool)` lama menganggap string `"false"` sebagai true.
- GitHub: tidak ada lagi `@github.local`; email non-null dari Socialite
  diperlakukan sebagai primary+verified.
- Penolakan: `Inertia::flash` pesan netral + redirect `auth.login`.
- `catch (\Exception)` dan pesan generiknya **tidak diubah**; logging adalah
  `BE-P3-007` di luar scope.

### `resources/js/utils/composables/usePageFlashToast.ts`

Perbaikan pendukung agar pesan penolakan benar-benar terlihat pada hard load
(redirect callback OAuth adalah full page load):

- `immediate: true` diganti `onMounted(showToast)` + `watch`.
- Penyebab: `immediate` berjalan saat setup layout, sebelum `<Toaster>`
  ter-mount, sehingga toast hilang. Inertia visit biasa tidak terkena karena
  layout sudah ter-mount saat flash berubah.

## Browser dan anomaly test

Browser dijalankan langsung (Playwright Chromium) terhadap
`http://localhost:3000`.

1. `/auth/google` → 302 ke `accounts.google.com` dengan scope
   `openid email profile` dan `redirect_uri` `/auth/google/callback`.
2. `/auth/github` → 302 ke `github.com/login/oauth/authorize` dengan scope
   `user:email`.
3. `/auth/google/callback` **tanpa state** → 302 ke `/auth/login`, toast error
   netral tampil, `/dashboard` tetap menolak (302 ke login).
4. `/auth/github/callback` **tanpa state** → perlakuan sama.
5. Callback dengan `state=forged-state&code=forged-code` → 302 ke login, bukan
   500.
6. Query DB: tidak ada user dengan email `%@github.local`.

Anomali input yang diuji di feature test: `email_verified` bernilai `"false"`
(string), email kosong, email beda case, akun dengan provider ID berbeda, dan
email milik akun soft-deleted.

## Acceptance criteria

- [x] Linking hanya bila provider menyatakan email verified dan email sama
      persis (case-insensitive, normalized).
- [x] Email unverified tidak login ke akun yang sudah ada.
- [x] Tidak ada email sintetis `@github.local`; GitHub tanpa email ditolak
      dengan pesan netral.
- [x] Test: unverified tidak linking, verified linking, GitHub tanpa email
      tidak membuat akun.
- [x] Regression test Google dan GitHub, termasuk percobaan takeover dan dua
      akun dengan email sama.

## Risiko dan mitigasi

- **Perubahan perilaku:** akun baru dengan email Google unverified dan login
  GitHub tanpa email tidak lagi dibuat otomatis. Ini disengaja dan sesuai
  acceptance; user diarahkan ke login/registrasi berbasis email + OTP.
- **Auto-link berbasis email:** OWASP menyarankan linking hanya dari sesi
  terautentikasi. Ticket memilih verified-email auto-link; risiko takeover
  dikurangi dengan exact match, subject ID utama, penolakan konflik provider
  ID, dan penolakan akun soft-deleted. Alternatif OWASP dicatat sebagai
  follow-up bila produk ingin lebih ketat.
- **Ketergantungan Socialite:** jaminan email GitHub berasal dari implementasi
  `GithubProvider` (scope `user:email`, `primary && verified`). Bila versi
  Socialite berubah, test feature/E2E harus tetap dijalankan.
- **Toast hard load:** perbaikan composable berlaku untuk semua halaman yang
  memakai `usePageFlashToast`; perubahan hanya menunda pemanggilan sampai
  `onMounted` dan tidak menggandakan toast.
- **Rollback:** revert commit code + docs; tidak ada migration, schema, route,
  atau dependency baru.

## Di luar scope (dicatat, tidak diubah)

- `BE-P3-007` — `catch (\Exception)` OAuth masih tanpa logging terstruktur.
- Session regeneration setelah `Auth::login()` belum ada (temuan baru, tidak
  ada di backlog).
- Rate limit pada route callback OAuth belum ada (temuan baru).
- Flow linking dari sesi terautentikasi (varian OWASP) belum ada.
