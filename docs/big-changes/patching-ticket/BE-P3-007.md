# Patching Ticket — BE-P3-007

## Status

- **Klasifikasi:** security
- **Prioritas:** P1
- **Ticket:** `BE-P3-007 — OAuth exception ditelan`
- **Evidence awal:** Confirmed
- **Scope:** callback OAuth Google/GitHub pada `OAuthController` dan regression test logging.
- **Status implementasi:** selesai, menunggu review manusia.

Status backlog pada `docs/big-changes/patching.md` tetap `Open`; agent tidak
mengubah status `Open` secara sepihak.

## Root cause

`OAuthController` menangkap `\Exception` pada callback Google dan GitHub, tetapi
hanya membuat toast generik lalu redirect ke login. Exception tidak dicatat,
sehingga kegagalan state OAuth, provider, atau konfigurasi tidak memiliki sinyal
operasional.

## Perubahan

- Callback Google dan GitHub menerima `Request` untuk mengambil route dan
  `X-Request-ID`.
- Kedua callback memakai satu private logger
  `logOAuthCallbackFailure()` agar metadata logging tidak diduplikasi.
- Event log `oauth_callback_failed` ditulis pada level `error` dengan context:
  `provider`, route name, request ID, dan `exception_class`.
- `X-Request-ID` hanya dipakai jika berbentuk UUID; header invalid atau tidak
  ada diganti UUID baru.
- Exception object, exception message, token, provider payload, email, dan PII
  tidak dimasukkan ke context log.
- Flash message dan redirect user tetap generik ke `auth.login`.
- Catch tetap menggunakan `\Exception`; scope tidak diperluas menjadi penelan
  `\Throwable`/programming error.

## Acceptance criteria

- [x] Kegagalan Google dicatat dengan level `error` dan metadata aman.
- [x] Kegagalan GitHub dicatat dengan level `error` dan metadata aman.
- [x] Correlation/request ID tervalidasi atau dibuat sebagai UUID.
- [x] Token, secret, raw exception message, provider payload, dan PII tidak
      dicatat.
- [x] Response user tetap berupa pesan netral dan redirect ke halaman login.
- [x] Feature test memastikan exception Socialite ter-log.

## Keputusan dan alternatif

- `Log::error()` dengan allowlisted metadata dipilih agar diagnosis tersedia
  tanpa serialisasi exception message/provider payload yang dapat memuat secret
  atau PII.
- `report($exception)` tidak dipakai karena framework dapat meneruskan detail
  exception ke logging stack default; ticket ini mensyaratkan context yang
  public-safe.
- Global correlation-ID middleware tidak ditambahkan karena merupakan scope
  terpisah `AUDIT-P2-005`; helper lokal menjaga perubahan tetap terbatas pada
  callback OAuth.
- Response header `X-Request-ID` tidak ditambahkan karena acceptance ticket
  hanya mensyaratkan correlation ID pada log dan tidak meminta perubahan
  response contract.
- Catch `\Throwable` tidak dipakai agar programming error tidak ditelan oleh
  callback-specific fallback.

## Risiko dan mitigasi

- Provider outage atau callback mismatch kini terlihat sebagai structured error
  log, sementara user tetap menerima pesan netral.
- Request ID hasil generate tidak dikirim ke browser; korelasi lintas layer
  tetap menunggu implementasi global request-ID pada ticket terpisah.
- Full suite belum sepenuhnya hijau karena failure job email di luar scope;
  OAuth targeted test dan seluruh E2E OAuth tetap hijau.
