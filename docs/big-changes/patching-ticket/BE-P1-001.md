# Patching Ticket — BE-P1-001

## Ringkasan

| Field | Nilai |
| --- | --- |
| Ticket | `BE-P1-001` |
| Klasifikasi | Dependency / security remediation |
| Prioritas | P1 |
| Baseline | `b73c643` pada branch `dev-zapp` |
| Status kerja | Siap dipindahkan ke `In Review`; status `Done` tetap untuk human |
| Scope | `symfony/mime` dan regression test MIME/email saja |

Ticket ini memperbaiki `symfony/mime v7.4.19` yang terdampak
`CVE-2026-45070`. Symfony mendokumentasikan bahwa versi `7.4.0` sampai sebelum
`7.4.22` terdampak dan `7.4.22` adalah versi perbaikannya:
[advisory resmi Symfony](https://symfony.com/blog/cve-2026-45070-email-header-injection-via-non-token-characters-in-mime-parameter-names).

## Bukti sebelum patch

- `composer.lock` dan runtime container mengunci `symfony/mime v7.4.19`.
- `composer audit --format=json` melaporkan `CVE-2026-45070` dengan advisory
  ID `PKSA-wtxr-p26d-nn42`.
- Regression test parameter name MIME merah pada versi lama: karakter CRLF
  pada parameter name belum ditolak.
- Root `composer.json` tidak mendeklarasikan `symfony/mime` secara langsung;
  paket tersebut merupakan dependency Laravel `v12.70.1` dengan constraint
  `^7.2`.

## Perubahan

### Dependency

Composer dijalankan di container dengan:

```text
composer update symfony/mime --with-dependencies --no-interaction
```

Hasil lockfile:

| Package | Sebelum | Sesudah | Alasan |
| --- | --- | --- | --- |
| `symfony/mime` | `v7.4.19` | `v7.4.22` | Versi pertama branch 7.4 yang memperbaiki advisory |
| `symfony/deprecation-contracts` | `v3.7.1` | `v3.8.1` | Dependency transitif yang ikut diperlukan Composer |
| `symfony/polyfill-mbstring` | `v1.43.0` | `v1.43.3` | Dependency transitif yang ikut diperlukan Composer |

`composer.json` tidak diubah. Menambahkan `symfony/mime` sebagai root
dependency ditolak karena akan membuat coupling constraint yang tidak perlu;
Laravel sudah memiliki constraint kompatibel dan lockfile menjaga versi hasil
remediasi.

### Regression test

Ditambahkan:

- `tests/Unit/Mail/SymfonyMimeHeaderSecurityTest.php`.
- Memastikan parameter name yang mengandung CRLF ditolak dengan
  `RfcComplianceException`.
- Memastikan parameter name valid tetap dapat diserialisasi.

Tidak ada production code, route, schema, atau flow bisnis yang diubah.

## Browser dan anomaly test

### Browser langsung

Browser langsung berhasil membuka aplikasi lokal di `http://localhost:3000/`.
Halaman landing merender normal. Link registrasi mengarah ke
`/auth/register` dan halaman registrasi merender seluruh kontrol form.

### Anomaly input

Pada `/auth/register`, input berikut sengaja dikirim melalui browser:

- nama: `<script>alert(1)</script>`;
- email: `not-an-email`;
- password pendek;
- password konfirmasi berbeda.

Submit tidak berpindah dari `/auth/register`. Browser melaporkan email invalid
dengan pesan native bahwa alamat tersebut tidak memiliki `@`; tidak ada akun
valid yang dibuat.

### Playwright E2E

Perintah desktop dan mobile dijalankan terhadap `http://localhost:3000`, tetapi
keduanya berhenti pada `globalSetup` sebelum test karena environment tidak
memiliki `E2E_ADMIN_EMAIL` dan `E2E_ADMIN_PASSWORD`. Credential tidak ditebak,
tidak dicetak, dan tidak ditulis ke report.

Status E2E: **Needs verification** setelah credential admin seeded disediakan
oleh environment yang berwenang.

## Risiko dan mitigasi

- Dependency update tetap berada pada major/minor line Symfony 7.4 dan tidak
  mengubah API aplikasi secara langsung.
- Tiga abandoned package masih terdeteksi oleh audit lengkap; remediation-nya
  bukan bagian `BE-P1-001` dan dicatat sebagai ticket dependency terpisah.
- Rollback dapat dilakukan dengan mengembalikan perubahan `composer.lock` dan
  menginstall ulang dependency dari lockfile sebelumnya; tidak dilakukan pada
  sesi ini.
