# Patching Ticket — BE-P1-003

## Ringkasan

| Field | Nilai |
| --- | --- |
| Ticket | `BE-P1-003` |
| Klasifikasi | Bug / transaction integrity |
| Prioritas | P1 |
| Baseline | Branch `dev-zapp`, source aktual 04-11-2026 |
| Status kerja | Siap dipindahkan ke `In Review`; status `Done` tetap untuk human |
| Scope | Recruitment job dispatch yang bergantung pada data committed |

Ticket ini memperbaiki dispatch job notification recruitment yang sebelumnya
terjadi sebelum `DB::transaction()` selesai. Laravel mendukung `afterCommit()`
untuk menahan dispatch sampai seluruh transaksi terbuka berhasil commit;
dispatch dibuang bila transaksi rollback. Referensi: [Laravel 12 Queue
Documentation](https://laravel.com/framework/docs/12.x/queues).

## Bukti sebelum patch

- **Confirmed:** `config/queue.php` memakai `after_commit => false` pada
  connection `database`, `beanstalkd`, `sqs`, dan `redis`.
- **Confirmed:** runtime container menggunakan `queue.default = redis` dan
  `after_commit = false`.
- **Confirmed:** tujuh dispatch berada di dalam transaction closure tanpa
  `afterCommit()`:
  - `ScreeningService`: pass, interview scheduled, revision, reject.
  - `FinalSelectionService`: final accepted, final rejected.
  - `CorrectionRequestService`: correction requested.
- **Reproduced:** regression test pertama merah karena job masuk queue saat
  outer transaction di-rollback.
- Job membaca ulang application, interview, atau correction dari database saat
  diproses worker. Karena itu, enqueue sebelum commit dapat melihat row yang
  belum committed atau mengirim side effect setelah rollback.

## Root cause

Job dipanggil langsung dari dalam `DB::transaction()` sementara konfigurasi
queue global sengaja tidak menunggu commit. Queue worker dapat menerima job
sebelum transaction boundary selesai. `delay()` bukan solusi untuk masalah ini
karena hanya menunda eksekusi, bukan enqueue dan bukan commit ordering.

## Perubahan

### Production code

Menambahkan `->afterCommit()` pada tujuh dispatch yang berada di dalam
transaction:

- `app/Services/Recruitment/ScreeningService.php`
- `app/Services/Recruitment/FinalSelectionService.php`
- `app/Services/Recruitment/CorrectionRequestService.php`

Tidak ada perubahan pada payload job, route, controller, schema, migration,
atau konfigurasi queue global.

### Regression test

Menambahkan `tests/Feature/Recruitment/RecruitmentAfterCommitDispatchTest.php`
yang menggunakan Redis queue dengan nama queue unik per test. Test mencakup:

- job dibuang ketika outer transaction rollback;
- queue tetap kosong selama transaction belum commit;
- job masuk queue setelah commit;
- seluruh lima jalur tambahan: screening revision/reject, final accept/reject,
  dan correction request.

`Queue::fake()` tidak digunakan untuk timing assertion karena fake Laravel
merekam `push()` langsung dan tidak mensimulasikan transport queue serta
transaction callback. Queue Redis terisolasi dipilih agar assertion menguji
boundary yang sebenarnya tanpa mengosongkan queue bersama.

## Keputusan dan alternatif

- **Dipilih:** `->afterCommit()` secara eksplisit pada dispatch yang berada di
  dalam transaction. Ini paling kecil, mudah diaudit, dan tidak mengubah job
  lain.
- **Ditolak:** mengubah `after_commit` menjadi `true` secara global karena
  dapat mengubah timing queued listener, mailables, notifications, dan job lain
  di luar scope ticket.
- **Ditolak:** memindahkan seluruh dispatch ke luar closure transaction karena
  memerlukan pengumpulan payload/job lintas jalur dan memperbesar perubahan
  tanpa manfaat dibanding mekanisme framework.
- **Ditolak:** memakai `Queue::fake()` untuk rollback timing karena fake tidak
  merepresentasikan enqueue transport yang sebenarnya.

## Risiko dan mitigasi

- Job sekarang dipastikan tidak dikirim bila transaction gagal; ini mengubah
  timing enqueue sesuai acceptance criteria, bukan isi email atau payload.
- Worker tidak dijalankan pada test regression; queue payload diverifikasi pada
  Redis queue terisolasi, sedangkan pemrosesan mail tetap dicakup test job yang
  sudah ada.
- Rollback patch cukup menghapus tujuh pemanggilan `afterCommit()` dan test
  regression; tidak ada migration atau data rollback.
