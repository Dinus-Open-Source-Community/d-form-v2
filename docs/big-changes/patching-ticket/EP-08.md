## Task 3 — Email-log migration rollback evidence

### Scope and safety

### AUDIT-P2-013 assertions

`test_email_log_recruitment_column_round_trip_preserves_nullable_event_rows_AUDIT_P2_013`
uses the existing disposable SQLite scratch connection, migrates the scratch schema,
seeds a valid recruitment application and an `email_logs` row whose `event_id` is NULL
and whose `recruitment_application_id` is populated, then rolls back through the target
migration boundary. It asserts that:

- `email_logs.recruitment_application_id` is absent;
- `email_logs_rec_app_fk` is absent from the email-log foreign-key columns;
- `email_logs_rec_app_idx` is absent;
- `email_logs.event_id` remains nullable; and
- the seeded email-log row remains readable with its NULL `event_id`.

The targeted test passed without a production migration change, so this is coverage
evidence rather than a reproduced local defect.
